# AnkiDroid 对比、代码审计与升级路线

审计日期：2026-10-11。基线：`main@e961d670cb04c81e8db1b547aee51bbd3a94d69e`。可见分支只有 main，无现存 PR；未发现 AGENTS.md。审计基于当前仓库源码，不把历史规划当作已实现功能。

ELS 面向高中英语专项训练；AnkiDroid 是成熟的通用记忆工具。借鉴其调度、主动回忆、撤销和数据可靠性，保留 ELS 分能力训练模型。没有复制 AnkiDroid 源码、接入 AnkiWeb 或改变原项目技术栈。

## 当前对比（含用户补充要求后的升级）

| 能力 | AnkiDroid / Anki | ELS 当前已实现 | 剩余差距 |
|---|---|---|---|
| 间隔复习 | FSRS、评级、牌组选项 | FSRS-6，独立能力记忆、可配置目标记忆率、每日新词预算、到期优先与撤销 | 个人权重拟合、长期保持率与负荷预测 |
| 主动回忆 | 正反向卡、输入、听写 | 选择、释义、拼写、现代 TTS 听音拼写，答后核对评价 | 错因分类、更丰富语境题 |
| 教材内容 | 灵活牌组与导入 | 管理员按单词/音标/词性/中文四字段预览导入、去重 | 教材由用户自行提供；册别/Unit 等非本轮必填 |
| 学习恢复 | 撤销、离线、同步 | 本人服务端进度与反馈恢复、幂等请求、完整撤销快照 | 现阶段专注 Web，离线和 Android 后续再做 |
| 复习管理 | 暂停、顽固卡、筛选 | 个人暂停/恢复、反复未独立记住次数、题型筛选 | 精细错题筛选、自动顽固词诊断 |
| AI 助学 | 通用卡片，需自行组织 | 可配置 OpenAI 兼容接口/OpenRouter，分组授权模型；辅导对话、长句主干/成分/理解检查、听力出题/定位依据 | AI 内容抽检与教学效果评估 |
| 语音 | 设备 TTS、录音内容 | 可配置现代云 TTS、音色、试听、语速、本人音频缓存 | 尚未用用户真实密钥进行音色试听 |
| 数据与账户 | 成熟本地数据/同步 | 认证、隔离、CSRF、加密密钥、两步验证、会话撤销、管理审计、个人 JSON 导出 | 自动备份、恢复演练、删除/留存策略与上线审计 |

模型权限仅限制允许哪些模型，没有调用次数或对话数量额度。听力原文与答案先留在服务端，提交后才反馈；生成内容有 AI 标识，不冒充教材来源。

## 已确认的缺陷

- `createSession` 忽略 review_states，按词条 ID 重复生成三组题；计数与实际选题脱节。
- 同词固定顺序重复出现，前面的选择题会暴露后面的拼写答案。
- 前端提交后将题目标为完成，立刻选择下题；错误反馈出现在下题旁边。
- 原临时调度不保存稳定性、难度或遗忘次数，无法称为 FSRS。
- 未匹配的中文释义永久 pending，既无后台判分，也无学生核对入口。
- Normalize 删除拼写中的内部空格与标点，导致不规范拼写被判对。
- Session ID 和重试请求只在浏览器局部保存；部分断网、刷新和多标签页路径不可靠。
- 原 CI 冒烟测试依赖第一题固定是 adapt，无法验证随机队列或真正复习。

## 实现与后续优先级

保留 Go/Next.js/PostgreSQL 及 Glass 风格，使用增量迁移，没有复制 AnkiDroid 源码或接入 AnkiWeb。FSRS 参数来自官方维护实现，未从旧计数伪造记忆状态。未匹配的中文释义仍由学生核对自评，AI 助学不自动污染正式判分。

用户明确当前只做 Web：教材由其专门导入四字段，Android 暂不开发。优先完成模型分组、自然语音与账户安全，不实现对话额度或调用次数限制。数据管理围绕 Web 账户隔离、导出与备份说明展开。

后续先验证用户实际导入的词库和真实供应商配置，抽检句子/听力质量，再完善自动备份及恢复、个人数据导入、FSRS 个性化和学习负荷统计。模型与模拟语音测试不能替代真实音色试听。当前尚无生产部署或主分支合并。
