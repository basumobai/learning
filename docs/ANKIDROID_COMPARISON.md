# AnkiDroid 对比、代码审计与升级路线

审计日期：2026-10-11。基线：`main@e961d670cb04c81e8db1b547aee51bbd3a94d69e`。可见分支只有 main，无现存 PR；未发现 AGENTS.md。审计基于当前仓库源码，不把历史规划当作已实现功能。

ELS 面向高中英语专项训练；AnkiDroid 是成熟的通用记忆工具。借鉴其调度、主动回忆、撤销和数据可靠性，保留 ELS 分能力训练模型。没有复制 AnkiDroid 源码、接入 AnkiWeb 或改变原项目技术栈。

## 对比

| 能力 | AnkiDroid / Anki | ELS 审计基线 | 本轮实现与剩余差距 |
|---|---|---|---|
| 间隔复习 | FSRS、记忆评级、可配置目标保持率 | 固定 10 分钟 / 1 天 / 3 天 | 接入 go-fsrs v4.0.0 的 FSRS-6，保存完整卡片状态与评级；使用默认参数、90% 保持率，尚未做个性化参数训练与设置 |
| 实际复习队列 | 新卡、学习卡、到期卡与牌组限制 | next_review_at 只用于首页计数，每次固定 15 题 | 到期优先、随机新题、题型和本轮上限、同词义每日题型避让；还缺每日新卡预算、暂停与顽固卡管理 |
| 主动回忆 | 正反向卡、输入答案、核对后评级 | 三种题型按固定词序；提交后直接切题 | 选择 / 英译中输入 / 中译英拼写可独立选择，反馈停留后评级，例句与设备 TTS；听写专用题型仍待开发 |

| 恢复与纠错 | 撤销、数据备份、离线使用、同步 | 浏览器只保存 Session ID；反馈刷新丢失 | 服务端恢复活动练习和反馈，答题/评级/撤销均幂等；撤销原子恢复 FSRS 状态、计数及到期时间；尚非离线应用 |
| 学习诊断 | 复习统计、未来负荷等 | 到期数与已练词数 | 北京时间今日记录和分能力统计；还缺保持率、负荷预测、顽固词、错因和长期趋势 |
| 内容互通 | apkg / colpkg 导入导出、AnkiWeb 同步 | 无导入导出 | 尚未实现 CSV / JSON / Anki 包互通和用户数据备份恢复 |

| 高中提分专项 | 可制作语境卡片，但需自行组织 | 无句子分析、阅读与听力专项 | 仍待开发；当前不应承诺能解决“认识单词但读不懂句子”或“听懂但记不住做题信息” |

## 已确认的缺陷

- `createSession` 忽略 review_states，按词条 ID 重复生成三组题；计数与实际选题脱节。
- 同词固定顺序重复出现，前面的选择题会暴露后面的拼写答案。
- 前端提交后将题目标为完成，立刻选择下题；错误反馈出现在下题旁边。
- 原临时调度不保存稳定性、难度或遗忘次数，无法称为 FSRS。
- 未匹配的中文释义永久 pending，既无后台判分，也无学生核对入口。
- Normalize 删除拼写中的内部空格与标点，导致不规范拼写被判对。
- Session ID 和重试请求只在浏览器局部保存；部分断网、刷新和多标签页路径不可靠。
- 原 CI 冒烟测试依赖第一题固定是 adapt，无法验证随机队列或真正复习。

## 本轮取舍

复用 Go API / Next.js / PostgreSQL 及现有 Glass 风格，增加增量迁移。FSRS 使用官方维护的 Go 实现，参数和学习步不自行编造；答题耗时仅记录，不声称属于 FSRS 算法输入。正确与提示仅限制评级，未匹配释义的自评有明确记录。自由练习保留日志但不污染正式记忆状态。

同词义每日题型避让以北京时间 00:00 为日界线；同一题型的到期学习步仍可当天再练。队列不将“能力项”包装为单词数。本轮新题上限不是每日上限。旧日志和到期时间保留，旧卡首次新评级时初始化 FSRS；不从旧 attempts 推测不存在的记忆参数。

## 后续顺序

1. **P1 内容可信**：教材版本、册别、Unit、词义与来源，导入预览、校对和差异报告；用许可清晰的内容建立正式词库。
2. **P1 数据可靠与安全**：认证和每用户数据隔离、备份导出/恢复、CSRF 与限流；仍限制测试环境，不部署生产。
3. **P2 复习管理**：每日新卡预算、目标保持率、暂停/顽固词、错题筛选、保持率和未来负荷。
4. **P2 离线与同步**：本地缓存、可靠提交队列、版本冲突、导出互通；不要把 localStorage 重试称为离线学习。
5. **P2 高中专项**：分句和句子骨架训练、搭配/熟词生义、听力关键词记录与选择；随后加入可审计的 AI 判分及人工纠错。
