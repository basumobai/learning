## 0. 执行摘要与当前事实

Learning 定位为面向广东高中学生的**语文、数学、英语、物理、化学、生物六学科 AI 智能学习平台**。版本 2.0 负责解决模型/权限、A/B/C 资源处理流水线、教材与专题分类、网盘导入、题库审核和后台操作；3.1 在同一数据模型上建立“**可靠评分 → 学习证据 → 错因确认 → 知识追踪 → 自适应训练 → 启发式辅导 → 复习/迁移验证 → 效果评估**”闭环。

仓库核验基线：2026-10-17 的 main@6dbbe97ebbeb9a6468e670753b6c0bfd4a13554d；开放 Draft PR [#11](https://github.com/basumobai/learning/pull/11) 是 v2.0 P0 审计和设计，不代表 P1–P8 已交付。后续开发开始前**必须重新获取最新 main 和 PR，不得把本日事实固定当作后续事实**。

- **现有技术**：Next.js/TypeScript；Go 标准库 net/http（不是 Gin）；PostgreSQL；Go Worker + PostgreSQL 持久化任务；Redis 已部署但不是当前核心队列；Docker Compose。
- **已有功能**：六学科专项、词汇与 FSRS-6、按需 AI 讲解、作文评审、广东英语听说训练入口、PDF 导入及审核、账户/身份组/模型授权、多端 Web。
- **已经引入**：go-fsrs/v4 v4.0.0（见 services/api/go.mod）。不得重复引入另一个逻辑等效调度器；评估升级时先检查 API 兼容与历史卡片迁移。

## 1. 项目目标、边界与真实成功指标

**最终用户体验**：学生能按北师大版 2019 英语教材 Unit 或其他学科教材自主学习，系统能基于已审核题目和真实作答证据判断下一步更有帮助的训练；学生做错后得到针对具体错因的简洁、可跳过、可验证的辅导，而不只是 AI 拼出一段答案。

核心要求：

1. 记录“**做了什么、独立表现如何、用了什么提示、错在哪里、后来是否能做新题**”的可追溯证据，而非没有依据的“掌握率 97%”。
2. 每一道题的原文、答案、评分标准、来源页码、知识点、修订版本与学生作答历史保持一致。
3. 推荐、复习和辅导共享同一个知识点本体及状态更新规则；永不把 AI 猜测直接写成学生能力事实。
4. 自主练习永远保留；AI 和算法服务不可用时，已审核题库、确定性评分、查看历史及已缓存的安全内容仍能工作。
5. 不限制用户每天 AI 对话次数或总体模型调用次数；可设技术性并发、单请求大小和安全/防滥用界限，不得借此暗中设置业务额度。
6. 主要支持手机、安卓平板和 PC 浏览器；Web 优先，原生 Android 非当前交付。
7. 数据、模型、语音、教学来源及许可均可追踪。用户作答的原始事实优先于生成的分析。

**成功指标**以 S0 测得的基线和标准评测集为准：确定性判分一致性、题目版本可恢复率、幂等错误率、错因人工确认一致率、弱项在新题上的迁移表现、复习长期效果、教学正确性、响应延迟、学生完成训练的操作成本。禁止虚构“准确率达标”；不得以模型数、页面数、调用量或打卡天数代替学习效果。

## 2. 与 v2.0 的依赖约定

属于 v2.0 的基础能力只使用或增量扩展，不另建平行模块：模型目录自动发现/测试/选择、身份组和任务路由；A（原始待处理）/B（识别待审核）/C（正式可用）资源状态；OCR/PDF 与网盘接入；教材/专题/试卷分类、审核发布；管理员基础导航与统一工作队列。

3.1 的边界是消费 v2.0 **已发布且有版本号的题目**、教材章节及知识点索引，并对其建立评分、作答证据、推荐与复习。v2.0 尚未交付的契约用接口设计和模拟测试先行，不能把尚不存在的库表当作运行时既成事实。

严格区别：**资源处理状态 ≠ 内容审核状态 ≠ 学生掌握状态 ≠ 复习到期状态**。不要把专题语法题强行归到教材 Unit；英语教材以北师大版 2019 新教材体系为目标，其他科目依实际版本、年级、考试年份归类。

## 4. 统一学习引擎及系统数据流

采用**单体模块化 Go 应用**，沿用 Next.js Web、PostgreSQL 权威数据和 v2 统一 Worker。不要为了概念先进强制迁移 Gin、引入第二套队列或拆大量微服务。

### 4.1 数据主链路

1. 管理员上传教材/专题/试卷 → v2 A/B/C、来源校验、版权审核 → 正式发布的题目版本和知识点关系。
2. 学生创建独立练习/模拟考试 → 服务端发放**不含正式答案**的可答题快照。
3. 提交 → 评分规则引擎产生分数、原始证据及可信度。
4. 错因诊断器从答案差异与步骤信息生成**候选**错因 → 学生确认/更正/待定。
5. 知识追踪器把有效证据按知识点角色、难度、是否提示、原题/变式题等更新状态；记录更新器与模型版本。
6. 复习调度器决定合适的回顾日期；推荐器在已发布题库中决定下一题、下一知识点；每日计划器组合建议。
7. AI 辅导器仅在允许的教学状态提供提示、讲解、相关已审核资料及变式验证。
8. 学习报告只聚合真实持久化事实；AI 可以解释，不允许编造指标。

建议业务接口清晰解耦：ScoringEngine、MistakeDiagnoser、SkillTracker、ReviewScheduler、PracticeRecommender、TeachingAssistant、EvidenceReporter。各组件可以在同一进程/Worker 内运行，用版本化事件和统一数据库连接，不建立相互覆盖状态的算法。

### 4.2 学习证据及版本不可变性

- 作答必须绑定 user_id、question_revision_id、scoring_rule_revision_id、question_skill_link_revision、attempt_id、session_id、client_request_id。
- 事实层（题目快照、学生原答案、时间、分数、使用提示）不可随模型升级而覆盖；AI 诊断和掌握度属于**派生层，可按版本重算**。
- 独立首次正确、使用提示后的正确、原题重做正确、新情境迁移正确须分别留证；置信度不足时显示“证据有限”，而不是精确百分比。
- 所有评分、知识状态、错因与推荐策略都要保存版本号；题目内容修订只影响新练习，旧练习、原分数和来源必须可查看。
- 分析导出不暴露跨用户数据；管理员只有必要的授权查询。对学生删除与导出建立可恢复/保留政策及日志。

## 5. P0：评分、历史修订与作答幂等（必须先落地）

### 5.1 评分引擎

支持单选、多选按**每道题已审核的标准**部分给分、多空独立评分、等价答案规则、数学表达式合法等价校验（在受限环境中）、主观题分要点和分步骤参考评分。确定性结果与 AI 参考评价分别存储；主观题未核实分数不能变成高置信度能力证据。超时、撤销、重复提交均有明确状态和不可篡改日志。

### 5.2 不可变题目快照

构建 QuestionRevision 和 ScoringRuleRevision，不在原题上原地修改被历史作答引用的内容；题干、选项、答案、页图/裁剪坐标、分值、解析、知识关联、来源文档修订全部可恢复。禁止旧练习因管理员编辑而只显示“请重新选题”。

### 5.3 一致性

- 答题提交以服务端原子事务与唯一幂等键防重。
- AI 外部调用可以重试但不保证供应商侧 exactly-once 收费；本地学习证据必须只更新一次。
- 评分完成/人工确认之后才触发必要知识状态更新；不得跨 Worker 因竞态重复计分。
- 部分失败时保留原答卷，可重新评分并给出新的版本，不静默篡改原评分。

## 6. P0：全学科知识点掌握证据（R03/R04/R06/R07，逻辑独立实现）

KnowledgeSkill 统一知识点本体，支持：学科、知识层级、教材/版本关联、概念定义、前置关系、关联题型及审核状态。一题可映射主要、辅助、前置和综合应用知识点；**某综合题答错绝不自动让所有关联知识点归零**。

UserSkillState 至少记录：有效独立作答、难度分布、提示使用、近期错误、最近复习、首次/变式题表现、知识状态等级、证据充分程度、规则版本和最近变化时间。状态等级建议“证据不足 / 初学 / 巩固中 / 基本掌握 / 熟练 / 易遗忘”，可另行根据验证数据评估 BKT、IRT、DKT 等，但不得在无校准时称作真正掌握概率。

SkillEvidence 每条附上 attempt_id、题目修订、知识点角色、评分可信度、推定误差、是否同题重复以及应用证据的决策依据。管理员修订知识映射后，历史证据保持原映射版本，可发起显式重算任务；界面标明重新计算时间与规则版本。

## 7. P0：错因诊断与错题闭环（R09 交互理念，独立实现）

### 7.1 结构化错因分类

英语：词义/熟词生义、词组搭配、句子主干、从句修饰、指代、逻辑转折、语篇推断、干扰项、听懂但遗忘、审题与时间。

数学/物理/化学/生物：概念、条件提取、建模、公式使用、计算、单位与数量级、图表、实验原理、推导断裂、文字审题；每科补充科目专属层级，不用一套笼统标签替代六科知识体系。语文补充文言实虚词、语句推断、阅读答题要点、作文结构/立意证据。

### 7.2 证据分级

AI 只能产生“候选错因 + 原题依据 + 学生答案依据 + 不确定性”；学生可“确认 / 更正 / 不确定”。只要没有强证据或学生确认就标为待定，系统可用作短期建议但不得当作学生长期能力事实。允许学生说明“只是手滑/输入错误”。

错题本支持按学科、知识点、错因、重复次数、未解决程度和最新验证筛选；可回看多次作答、原题再做、新变式验证、对应讲解、纠正记录。错题“已理解”和“在全新题上证明掌握”分开标记。

## 8. P0：自主练习和智能强化双模式

**自主练习**：学生选择学科、教材版本、册次/Unit/章节、知识点、题型、难度、题量、计时与是否优先新题。避免同一英语词在不同题型连续曝光答案；词汇四选一严格继承普通整题 6 秒、困难/绝望整题 3 秒的既有要求，不偷偷改计时口径。

**智能强化**：综合知识状态、待复习、近期失误、题目难度、学习目标、题型分布、学生的自主排除项和重复曝光情况进行可解释选题。每次推荐保存 decision_log：候选数、排除原因、权重/版本和最终原因，确保可回放、可诊断偏差。

典型闭环：电磁感应综合题失败 → 判断错误是否发生在楞次定律/条件提取 → 简单前置题 → 不同情境变式 → 回到综合题。系统不能靠学生记住原题答案就给出“完全掌握”的结论。题库不足时**明确告知**，不可捏造题目来源或使用未审核题冒充正式真题。

## 9. P1：FSRS 扩展、复习与每日计划（R03/R04/R05）

保留目前独立词义、拼写、听音拼写等 FSRS-6 状态与撤销逻辑。为适合主动回忆的中文义项/搭配、古诗文背诵、默写、理科公式条件、概念辨析等构造独立 ReviewItem；高阶证明、建模、实验分析等优先通过**新题迁移练习**巩固。

- FSRS 状态、知识掌握证据、题目再练任务彼此分开，避免同一次提交被不同算法重复更新。
- 由服务端 go-fsrs/v4 作为唯一调度权威；若参考 ts-fsrs 的“预览四个选项后果”交互，也必须使用服务端结果。复习历史可重算，撤销能原子恢复。
- 可逐步评估个性化 FSRS 参数优化，但必须满足足够历史样本、训练验证与失败回滚条件，不给新人编造参数。
- 每日计划结合可用时间、重点/暂停学科、近期考试与待复习任务，输出“为什么建议学这几项、预计用时、能否跳过”。学生能编辑；不强制打卡、不以点击量代替掌握。

## 10. P1/P2：六学科内容及英语专项升级

### 10.1 英语优先（北师大版 2019）

按教材 → 册次 → Unit/Lesson → 义项/语境组织词库；每条支持音标、词性、多义、搭配、例句、易混词、熟词生义，并保留管理员四字段导入的兼容路径。Unit 同步与跨 Unit 乱序、听音拼写、英中选择、中英拼写、主动回忆共存；不能依赖词表顺序构成虚假熟练。

**交互式长难句**：学生先自行选择主谓宾/表语、定位从句、修饰范围、逻辑连接并尝试翻译；AI 仅基于原文片段标注和可检查的范围提供提示；可随时跳过或直接看答案；最后用不同内容但同语法结构的句子验证。渲染使用安全的结构化标注，禁止执行模型提供的 HTML/JS。

**阅读能力链**：词汇不懂、单词认识但句子断裂、逻辑/指代错误、推理错、选项迷惑分别进入对应强化。学生能从阅读题跳到其关键句、核心词义、同类阅读验证，不做松散孤立入口。

**听力信息保持**：时间、数字、人物、地点、转折、关键词笔记、听后复述、分段重听、语速变化；区分“没听懂”和“听懂了但没记住”，由不同练习验证。

**广东英语听说**：保留 A 模仿朗读、B 三问五答、C 故事复述；在真实语音服务可用时增加录音上传、ASR 文本、朗读完整性、语速/停顿、内容要点与发音参考维度。区分转写可信度、口语表达与发音分析，不冒充官方机器评分；未交卷 B/C 原文和答案服务端保密。

### 10.2 其余五科

语文：古文/名句检索、阅读证据定位、作文多评审改进建议；数学：步骤/表达式、推导与证明证据；物理：建模、图像与单位核查；化学：实验条件、反应与守恒；生物：遗传推断、实验变量与图表。所有学科均依据**具体考试年份和审核规则**提供专项题型，避免把广东高考卷型跨年度混用。

## 11. P1/P2：引导式 AI 辅导、已审核资料 RAG（R01/R06/R08/R09）

### 11.1 教学状态机

未开始 → 独立尝试 →（学生主动请求提示）→ 已交卷 → 诊断 → 补救学习 → 新题验证 → 已完成。学生始终可直接要求完整讲解，也可只要一个小提示。AI 不为增加 Token 而拖长对话。前端和服务端同时执行状态授权：未交卷不得从讲解、RAG、缓存、复习预览或任务日志取出本题参考答案。

### 11.2 正式资料检索

通过 v2 审核入库资源建立检索索引。每个 chunk 至少具有 document_revision_id、实际物理页码、标题/章节、内容类型、权限范围、审核状态和文本/图像定位信息。生成回答时区分：

- **原始教材/试卷引用**（可点回原件和页码）；
- **管理员审核结论**（已确认的参考解析/题目）；
- **AI 补充解释**（明确标识模型生成与可能错误）。

检索权限以当前学生对正式资源的访问权限为准；未审核的 B 区资料和无证据的 AI 摘要不得作为权威来源；日志脱敏，不把全本 PDF 无意义塞给模型。没有可靠证据时明确“不确定/未查到”，而非伪造页码。

### 11.3 长对话

保留重要教学目标、学生当前难点、已讲过的内容和引用证据。按模型上下文预算对历史进行可追溯压缩、检索相关片段与按需展开；保留原消息，不能在摘要后删除事实。估算 Token、首字延迟和失败时提供清楚反馈。用户模型权限沿用 v2 身份组机制。

## 12. P1：学习报告与可解释个性化（R02/R03 的产品经验）

学生仪表盘包含每日/每周有效独立练习、各科题量和时间、到期复习、已解决/新增弱项、按难度表现、首答/复答、用提示后的正确率、同题 vs 变式题的迁移成绩、重复错因。

周/月报告引用数据库聚合数值，并提供“证据支撑的改善、遗忘风险、下一步建议”，不制造精确能力百分比。显示数据不足、未评分、由 AI 初评等状态；个人学习数据默认只对本人和最小必要授权管理员开放，默认无公开排名榜。

## 13. P2：广东高考整卷模拟

按照“考试年份 + 学科 + 卷型 + 题型结构版本 + 分值/时间规则”组卷，记录全部题目修订和组卷快照。正式计时及截止由服务端负责；答案草稿可恢复、幂等交卷、超时提交、考后分板块复盘与时间诊断。标明“平台模拟卷”，禁止冒充官方试卷；题库没有对应年份准确题型或总分规则时拒绝宣称官方对齐。

正式考试/限时练习的答案永不通过离线缓存、AI 接口、预览接口或浏览器调试响应提前暴露。

## 14. 学生体验：现代 Web、弱网与多端（R02/R06/R07）

参考成熟 LMS 的学习流程和 Kolibri 离线设计原则，保留 Learning 自身的 Apple Liquid Glass 启发式风格；不复制他人截图/图片资源。统一页面区块：**今天学什么 → 选择学习路径 → 独立作答 → 按需纠错 → 迁移验证 → 复习计划**，降低层层跳转。

- 手机：单列，作答控件优先，提示/讲解抽屉按需展开；完整触控与键盘焦点。
- 平板：题干/笔记/讲解可切换双栏，适配横屏与竖屏；支持手写或文本草稿（条件具备时）。
- 桌面：题干与步骤/资源并排；宽屏留白合理。
- 所有设备：字体放大、降低动效、无障碍标签、深色模式、公式/图像缩放、低带宽音频反馈。
- PWA 只缓存获得授权且允许离线的公开或学生自有内容；草稿与幂等同步队列按用户隔离，登出清理敏感缓存；正式考试/受保护答案**不缓存**。
- 不新增巨大单页面：题目渲染、评分反馈、知识诊断、模型设置、AI 讲解、同步状态、统计组件拆分；通用 TypeScript DTO/API 封装与后端契约同步更新。

## 16. 工程可靠性、安全与 AI 质量

### 16.1 Worker、数据与恢复

复用 v2 统一持久化任务表和 Go Worker，增加任务 lease/fencing、失败重试、取消、死信或人工处理、租约外写入拒绝、任务去重与状态可追踪；Redis 若使用，仅做可恢复通知/缓存而非学习数据唯一来源。

评估 PostgreSQL 存大 PDF/页图的增长瓶颈，按内容哈希与引用计数迁移到本地对象存储或 S3 兼容存储；迁移必须双读校验、可回滚，不删除未核对的源文件。备份要覆盖数据库、资源对象、加密密钥及恢复说明，定期在隔离环境演练。**不得因升级自动清空生产用户学习记录**。

### 16.2 AI 模型路由和质量

服务商自动发现、模型授权与列表多选归 v2，不重复开发。v3 只提出模型质量与教学任务画像：词汇释义、句法、阅读、OCR/PDF、主观评分、语音理解/合成、RAG 辅导等区分“速度/成本/质量/能力”。管理员变更模型/提示词必须先在标准评测集比较。后台显示真实或估算 Token、费用、TTFT、总耗时、失败率、超时率、语音质量抽检与教学错误类型，**不把费用估算说成实际账单**。

### 16.3 教学质量验证

构建六学科人工核对的评测集，覆盖英语长难句、阅读、听说/信息记忆、作文，语文阅读/作文、数学推导、物理建模、化学实验、生物图表/遗传。校验事实正确、推导正确、原题忠实、引用真实、错因可靠、讲解可懂、学生迁移成效、结构输出、速度和成本；自动规则、AI 评判、人工核查分别记载。关键模型降级不能只因为便宜而直接替换；质量下降须提示、回滚或停止使用该任务路由。

### 16.4 权限与注入防护

模型看见的 PDF/网页文本一律当作不可信输入，不能执行文件中的指令；无权访问服务端密钥、后台管理 API 或别的学生记录。检索、向量片段、AI 历史及音频缓存均按用户/角色/资源状态限制访问。服务端验证模型授权、题目答案保密、截止、会话状态；敏感日志脱敏，保持 HTTPS、CSRF 和加密密钥治理。

## 18. 必须通过的端到端验收场景

1. **物理知识迁移**：连续做错电磁感应题 → 识别待证错因 → 前置楞次定律训练 → 新变式正确 → 记录按证据改善，而非直接给满分掌握率。
2. **英语逻辑关系**：识得大部分单词但阅读转折判断错；系统给出逻辑关系专项而非泛化为“英语差”。
3. **同题背答案**：同一道题二次做对但新题失败，不认定完全掌握。
4. **多选部分分**：少选正确选项按题目实际审核规则给分，反馈可复算。
5. **旧题回看**：管理员改题后仍可查看该学生原卷、旧答案与原分值。
6. **纠正 AI 错因**：学生说明输入失误并更正；待定 AI 猜测不得变成固定能力结论。
7. **复习幂等**：双击、离线重放、Worker 重试后同一答题事件只影响一次状态。
8. **英语长句**：学生圈定主干/修饰对象，AI 提示错误位置，再用新句验证。
9. **AI 评分失败**：错误引用、无根据评分或 JSON 结构损坏时不予正式确认；允许人工核查/重评。
10. **正式资源权限**：B 区未审核 PDF 与试卷答案不能被 RAG/模型/浏览器缓存提前暴露。
11. **网络与恢复**：中途断网、服务重启、数据库备份恢复后完整保护账户、题目修订、学习证据与资源回链。
12. **许可与来源**：所有新增外部代码有许可与提交版本记录，MIT 声明正确，AGPL/GPL/自定义限制代码没有混入 MIT 原创组件。

## 19. 测试、PR 与执行纪律

**每个阶段**必须记录实际执行的命令、环境、成功/失败与覆盖不足：

- 单元：部分评分、知识更新、复习调度、错因规则、排序/随机性、取消撤销。
- PostgreSQL 集成：增量迁移、并发、作答幂等、租约、用户隔离、题目历史、重放回填。
- Web/PWA：手机/平板/PC、触控/键盘、弱网/刷新/多标签、深色、减少动效和答案保护。
- AI 教学：固定评测样例 + 真实供应商小规模抽验，区分模拟和实付模型，结果不可互称。
- 版权合规：SBOM/依赖清单、LICENSE/NOTICE 校验、来源链接、源提交 pin、图片字体与模型/数据许可审计。

开发准则：先分析最新 main 与开放 PR；设计评审后在独立分支开发，每阶段分 PR，不直接合并 main，不部署生产，不读/传生产密钥，不删数据，不复写已有 v2 能力。README 简洁，架构、验收与许可来源记录放 docs；每个 PR 必须写“完成/未完成/兼容性/风险/测试实际结果”。

## 20. 给开发 AI 的执行指令

1. 先重新核查 GitHub 现状及 PR #11 后续变化，把本计划与 v2 文档逐项去重；把每个需求标记“已实现 / 部分实现 / 缺失 / 待核实”。
2. **正式编码前**提交四份设计成果：A. 现状与差距；B. 智能学习系统模块与状态流；C. 迁移/版本/安全/回滚方案；D. S0–S8 测试和验收方案。未经确认不进行大规模修改。
3. 外部参考遵守 [OPEN_SOURCE_REFERENCES.md](OPEN_SOURCE_REFERENCES.md) 的**设计参考与代码复用分离**、许可证核验与版权保留规范；优先 MIT 的 go-fsrs、Open Notebook、Kolibri 等成果，严格禁止把 AGPL/GPL/非标准社区许可代码直接纳入 MIT 原创模块。
4. 先完成评分与不可变修订，再处理知识追踪/错因/推荐；确保任何时候都不牺牲账户隔离、答案保密或历史学习记录。
5. 以可运行 PR 和真实验收结果交付，不用“开发计划已经写好”冒充功能完成。

**最终标准：Learning 不仅能记录学生做过什么，还能在证据可信、教学正确、数据可恢复的前提下，解释学生可能不会什么、为什么不会，以及怎样通过新题验证下一步学习是否有效。**
